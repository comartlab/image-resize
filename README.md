# Image Resize

A native macOS app for resizing, cropping, watermarking, and converting one image, a selection of images, or entire folders. The universal app contains both arm64 and x86_64 executables and targets macOS 12 or newer. Written in Swift with AppKit, ImageIO, CoreGraphics, Accelerate, and Quick Look Thumbnailing; no third-party runtime, network calls, or upload service.

## Install and use

Download the universal DMG from [GitHub Releases](https://github.com/comartlab/image-resize/releases/latest), open `Image Resize-1.12-universal.dmg`, and drag **Image Resize** to **Applications**, replacing the previous version if installed. Launch the app, drop images or folders (or use **Add…**), set the size, choose the **Format** and an output folder, and click **Resize**. **Subfolders** controls folder traversal when importing. Select rows and press Delete to remove them.

Choose **Keep original dimensions** in the size menu to export without resizing. Watermark, strength, format, quality, metadata, crop, and output-folder settings all remain available. The size fields are hidden, the action becomes **Export**, and files are written even when their dimensions do not change. With a crop applied, the selected pixels are exported at their original scale, so the output dimensions are the crop dimensions. Reset the crop to preserve the full image dimensions. This mode is remembered across launches.

Choose **Optimized for web** in **Format** for small JPEG/PNG exports. The app converts to 8-bit sRGB, removes source metadata, preserves transparency, and automatically chooses the smaller JPEG or lossless PNG for opaque images. JPEG quality starts at **75%** and is remembered separately from your regular quality setting. Lower it for smaller JPEGs or raise it for more detail; transparent PNGs retain their alpha and do not use lossy JPEG quality. The metadata checkbox is disabled in this format, and your regular metadata preference returns when switching formats. Size, crop, watermark, and output-folder settings still apply, including **Keep original dimensions**. Web optimization never reduces pixel dimensions beyond your selected size. File sizes depend on image content and quality; it does not impose a kilobyte limit.

Each image row shows an estimated output size below its target dimensions, and the footer shows the batch estimate. Estimates update after changes to size, crop, format, quality, metadata, or watermark. They use a temporary trial export with the actual encoder and settings, including automatic JPEG/PNG selection for web output. No destination folder is needed to estimate, and trial files are removed after calculation. Skipped images contribute zero bytes; partial totals are labeled “so far,” and unavailable estimates are identified rather than counted as complete. Actual file sizes replace the estimates after export.

Estimation is debounced and runs one image at a time on the shared background image worker, prioritizing a selected image. Import and the interface remain responsive; starting an export cancels estimates without waiting for the whole queue. A native decode or encode already in progress finishes its current stage before cancellation takes effect. This avoids concurrent full-resolution estimate/export allocations. Estimates are approximate because files or encoder behavior can change before export.

Select any image and click **Preview & Crop…**, or double-click its row, to open the crop preview. Drag to draw a rectangle, drag inside it to move it, or drag an edge/corner handle to resize it. Choose **Freehand**, **1:1**, **9:16**, **16:9**, **2:3**, **3:2**, **4:5**, or **5:4**. **Undo**/**Redo** step through edits; **Reset** removes the draft crop, and **Cancel** discards the draft. **Apply to Batch** uses the crop for every queued image. **Reset Crop** in the main window removes the applied crop; Edit → Undo can restore an applied/reset crop during the session. The chosen crop and aspect preset are remembered across launches.

The crop uses coordinates relative to the upright image, so it scales to each source's dimensions. Fixed ratios fit within that relative crop area on images with different shapes. Cropping happens after orientation/layer flattening and before reduction and watermarking. In the reduction modes, the existing skip rule applies to the cropped area: images already at or below the selected output bounds produce no output. The crop preview remains available for these images so you can adjust their framing.

To watermark the output, enable **Watermark**, enter your text, and adjust **Strength** from 0–100%. The initial strength is 25%; 13% matches the previous faint treatment. Zero strength leaves the image unmarked. The eye button previews the selected image (or the first image if no row is selected); an open preview updates after you adjust strength. Preview is disabled for images that will be skipped. Hollow text repeats diagonally across the image, with size and spacing proportional to the output dimensions. The watermark starts disabled on first use, with an empty text field.

All applied controls are remembered immediately: crop and aspect preset, resize mode, pixel sizes, percentage, output format, compression quality, metadata, subfolder choice, watermark text/enabled/strength, and output folder. Window size and position are also restored. Edits are retained even if you quit while typing without running a batch. Pixel and percentage values are remembered separately when switching modes. Updates preserve existing preferences; version 1.3 adds the new strength preference with a 25% default.

The supplied build is ad hoc signed and **not notarized**, because this machine has no Developer ID certificate. A downloaded copy may require the app-specific approval described in [Apple's opening-apps guide](https://support.apple.com/en-us/102445). Public distribution without that approval requires Developer ID signing and Apple notarization. The scripts support both.

## Behavior

- File drops enter the queue immediately without opening or validating their image data. Visible-row previews and dimensions load on a separate background worker; Resize never waits for previews. Pending preview requests are cancelled during exports. Corrupt or unsupported inputs remain queued and report a per-file failure during processing. Folder discovery lists paths in small batches; Resize can be clicked while listing and automatically begins exporting once the complete path list is available, so newly written outputs cannot enter the same batch. Clear cancels discovery and preview work, and removed files stay removed even if an overlapping folder listing is still running.
- Size by longest edge, fit within width × height, width, height, or percent. Proportions stay locked; images are never enlarged. In these reduction modes, images already at or below the selected bounds are skipped completely and produce no output file. Equal-size targets and percentage reductions that round to unchanged dimensions are also skipped. Pixel rounding can change the ratio by less than one pixel.
- **Keep original dimensions** bypasses resampling and the fitting-image skip rule. It exports at the source’s upright pixel dimensions, or the crop’s pixel dimensions when cropping is enabled.
- Native Lanczos-5 resampling is selected automatically for reductions; there is no algorithm selector.
- Choose JPEG, PNG, TIFF, HEIC, original format, or **Optimized for web** from **Format**. JPEG is the default on first use; an existing saved format choice is restored on upgrade and subsequent launches. Inputs are still images macOS ImageIO can decode, including JPEG, PNG, PSD, layered TIFF, HEIC and common bitmap formats. Animated and multipage inputs are rejected with a reason.
- PSD and Photoshop layered TIFF inputs use their saved visible composite, flattened into working pixels before resizing or watermarking. This preserves the baked appearance of hidden layers, opacity, masks, and effects. Outputs contain no original editable layer stack, even with **Keep metadata** enabled. PSDs need a usable composite saved with **Maximize Compatibility**; otherwise the app explains how to resave them or export a flattened TIFF. The source file and its layers stay intact. A multipage TIFF is a different format and remains unsupported.
- Regular formats retain RGB color profiles. Grayscale and CMYK images are color-managed into sRGB. Explicit PNG/TIFF formats retain 16-bit sources; JPEG/HEIC are 8-bit. **Optimized for web** always converts to 8-bit sRGB. HDR/float images become SDR.
- PNG/TIFF preserve transparency. JPEG/HEIC flatten it onto white. **Keep metadata** retains supported camera/date/GPS metadata and updates dimensions/orientation; cropped exports also remove recognized subject/face-region coordinates that would refer to the old framing. Turn metadata off to remove descriptive metadata while keeping the color profile.
- Originals and existing output files are never replaced. Name collisions get `-2`, `-3`, etc. All output is placed directly in the chosen folder. No directory hierarchy is copied.
- In reduction modes, skipping applies regardless of watermark, format, or metadata settings. The image list shows **Will skip** before processing and **Skipped** afterward; the batch summary counts saved, skipped, and failed files. If macOS cannot encode the original format of an image being exported, a PNG is saved with a note in **Details…**. Transparent PSDs also use PNG when **Original format** is selected, because the native PSD writer does not preserve their compatible composite accurately. Opaque PSD outputs can contain one new flat raster layer; the original layer stack is never retained.
- Processing runs off the main thread, one image at a time, with vImage's native acceleration. Cancel finishes the current image and stops the remaining batch. Individual failures do not stop the batch. There is no application-imposed pixel-dimension or memory-budget limit on input or output images. Available system resources and the selected codec determine which images can be processed.

Version 1.12 adds The Commercial Art Lab attribution, website and GitHub source link to About, GPL-3.0-or-later licensing, and a bundled corresponding-source archive. Version 1.11 adds background per-image and batch output-size estimates and actual per-file sizes after export. Version 1.10 adds **Optimized for web** with automatic JPEG/PNG selection, 8-bit sRGB conversion, stripped metadata, and separate saved web quality. Version 1.9 adds **Keep original dimensions** for exports without resampling. Version 1.8.1 labels the combined image preview and crop tool explicitly. Version 1.8 adds batch cropping with an interactive preview, aspect presets, freehand rectangles, Undo/Redo, Reset, and saved crop settings. Version 1.7 removes import-time image validation and bulk thumbnail decoding, uses cancellable native Quick Look previews when no embedded thumbnail is available, and updates only the affected visible row as each file finishes. Version 1.6 makes JPEG the default output and labels the format selector. Version 1.5 explicitly accepts PSD and layered TIFF inputs and checks Photoshop composite compatibility. Version 1.4's skip behavior and version 1.2's removal of image-size and memory-budget caps remain in place: ordinary 8-bit images use 4-byte working pixels rather than 16-byte float pixels, and the full-resolution working buffer is released immediately after scaling. Higher-depth images keep float processing to preserve precision.

Reducing pixel dimensions does not guarantee fewer encoded bytes for every format/quality setting. PNG/TIFF and high-quality JPEG can be larger than a compressed source. This app crops and reduces dimensions; it does not target a maximum file size, edit layers, distort proportions, or change print dimensions/PPI independently.

## Build and verify

Requires Xcode or a macOS Swift toolchain and SDK. No package downloads are needed.

```sh
scripts/build.sh
scripts/test.sh
RESIZE_TEST_ARCH=x86_64 scripts/test.sh
scripts/test-crop-editor.sh
RESIZE_TEST_ARCH=x86_64 scripts/test-crop-editor.sh
scripts/benchmark.sh
scripts/package.sh --skip-build
```

On Apple silicon the Intel tests require Rosetta. In restricted execution environments, native HEIC encoding and DMG creation may need access to system services outside the execution sandbox. The distributed app itself is not App Sandbox-restricted.

To build a notarized release after configuring a Developer ID certificate and notarytool keychain profile:

```sh
DEVELOPER_ID_APPLICATION='Developer ID Application: Your Name (TEAMID)' \
NOTARY_PROFILE='your-notary-profile' scripts/package.sh
```

`APP_VERSION` and `APP_BUILD` optionally set the release version/build. `scripts/Icon.swift` reproduces the icon; compile it and pass an iconset output directory followed by an `.icns` output path.

## Verification

80 integration groups pass for arm64 natively and x86_64 under Rosetta on macOS 15.6.1: bounds/proportions, all output formats, every EXIF orientation (pixel verification), alpha/white matte, resampling alias suppression, metadata/ICC, collision/source safety, corrupt/animated/multipage rejection, 16-bit precision, grayscale conversion, and watermark rendering. Skip checks cover all reduction modes and formats with watermark and metadata choices, equal bounds, 100%, rounding to unchanged dimensions, mixed batches, source/output integrity, and an oriented image exceeding only one fit bound. Watermark checks cover faint outlines on light/dark backgrounds, Unicode, text limits, tiny and portrait/landscape outputs, alpha, P3 color and 16-bit precision. Strength checks verify zero-strength pixel identity, increasing contrast on white/black/colored backgrounds, and rejection of invalid values. Large target bounds above 100,000 and integer-boundary rounding are also tested. The AppKit folder-import-to-export workflow, watermark preview/export, and settings persistence after relaunch without running a batch were exercised through the UI using a separate app identifier to preserve the user's live session and preferences. Version 1.4 GUI checks processed a 10-image folder at a 256-pixel bound with watermarking enabled: three larger images produced 256 × 256 outputs, seven smaller or equal-size images were skipped, and all source checksums remained unchanged. Both architectures compile with deployment target 12.0; physical Intel hardware and a macOS 12 runtime were not available for testing.

Version 1.5 checks genuine layered PSD and Photoshop TIFF documents at 8 and 16 bits, including hidden layers, layer opacity, composite transparency, ICC retention, layer-resource removal with metadata enabled, original-format output, compatible-composite rejection, and fitting-image skips. Grayscale and CMYK PSD transparency are also covered. Photoshop 2026 opened the generated layered fixtures with the intended appearance; copies saved by Photoshop itself passed supplemental exports on both architectures. The GUI accepted a single PSD and a folder containing five layered PSD/TIFF files, exported correct 40 × 24 flattened PNGs (retaining 16-bit depth where applicable), and showed clear compatibility instructions for a PSD without merged data. All source checksums stayed unchanged.

Version 1.6 passes the same 38 integration groups on both architectures. The default-settings reduction produces a real JPEG with a `.jpg` extension. A separate fresh AppKit session started with JPEG selected, exposed all five format choices, accepted PNG selection, and restored PNG after quitting and reopening without running a batch.

Version 1.7 passes 48 integration groups on both architectures, including uninspected queues, processing-time validation, stale completions after Clear/Remove/reimport, stable batch snapshots, streamed discovery, cancellation, subfolder traversal and output-folder exclusion. Listing 600 empty/corrupt JPEG-named files took 0.013 and 0.019 seconds and accepted every path before processing. These local synthetic measurements exclude UI rendering and are not predictions for network volumes. The AppKit workflow queued 1,001 inputs with Resize enabled before all metadata/previews were ready, then saved 1,000 reductions to 40 × 20 PNGs in 1.5–1.6 seconds and reported the corrupt file during processing. A repeat run verified all 1,000 source checksums and 1,000 existing output checksums stayed unchanged while 1,000 new collision-safe outputs were added. Native background PNG, layered PSD and layered TIFF thumbnails were verified, including immediate cancellation. The final build restored saved settings after relaunch.
